# League Team Duel

Team Duel is a rated league season format for 8, 10, 12, or 14 selected players. Two equal squads earn one squad point per game win; individual ratings use the four actual participants. The standalone `/team-duel` tool retains its separate, unrated scheduling rules.

## Flexible drafts

Fixture-free drafts use **CP-SAT** only. There is no scheduling-mode selector or browser exhaustive-search fallback. Shuffle searches squad splits and displays squads only after verifying a valid schedule. It prefers unseen splits with similar total ratings but considers every split when checking feasibility. Squad selection is not guaranteed globally optimal. Cards distinguish solver-proved objectives from valid results found within the budget.

Interactive solves disable presolve so native preprocessing cannot consume the response window; offline benchmarks retain presolve by default. The hard meeting caps and 55/45 season check still apply to every preview. Refresh schedules keeps the current squads; Shuffle searches for another verified split.

**Maximum match win probability (%)** is an editable hard ceiling, defaulting to **65%**. A value of 65 requires every match to remain within 65/35. New drafts default to at most **2 games with the same partner** and **3 against the same opponent**. CP-SAT searches, client result validation, and database save/generate validation all enforce the selected ceiling using current ratings. Changing the percentage invalidates old previews; the selected value is saved with the plan. Older plans without a percentage use 65% when saved or generated again. Existing fixtures are not re-rated or rewritten by this rule.

**Maximum ranking-point difference** defaults to **No limit**. Choose **Set limit** to reveal a nonnegative whole-number input, initially **400**. Every match must satisfy `highest rating − lowest rating ≤ limit` across all four participants, using current, unrounded league ratings. Zero permits only identical ratings. Server prefilters, CP-SAT candidates and warm starts, client decoding, and database saves/generation all enforce the cap. It is saved with the plan, appears in limit summaries, and is never relaxed automatically. Changing it clears previews and feasibility proofs. Older plans without the field use No limit.

A successful Shuffle explicitly confirms that the conditions can be met. A roster-wide impossibility message requires proving every split infeasible (35 splits for eight players; 1,716 for fourteen). Each click runs up to three bounded search batches. An unfinished check reports how many splits have been ruled out and offers **Continue checking conditions**. Continuations skip only proven failures and retry unresolved splits with more time. Proofs reset when roster, ratings, or limits change. If a later shuffle times out after finding a valid split earlier, it keeps that verified split and explains that no new split was found. Refresh-only failure refers to the current squads. Empty/invalid previews cannot be saved, and no search automatically relaxes the ranking-point, percentage, or repeat limits.

Before CP-SAT, Shuffle runs a roster-wide prefilter pass, capped at five seconds. It rejects splits with too few distinct allowable matches, insufficient partner/opponent capacity, shared capacity bottlenecks, or season-win bounds that cannot reach 45–55%. Small maximum-flow networks relax the real scheduling constraints: failure proves impossibility; passing still requires CP-SAT. Unvisited splits receive the same checks before their solve. Rejections count toward the existing resumable proof, and no split is discarded merely for a large total-rating gap. Tests preserve known valid schedules for all supported sizes and compare rejected examples against CP-SAT.

CP-SAT uses one solver thread. Fixed-squad refresh has a shared 24-second budget. Each Shuffle API batch searches splits for up to 20 seconds, with a shared 40-second budget including schedule options after finding a split. The roster pass minimizes the worst match imbalance; the second option uses the variety objective. Exact season-probability rejection applies throughout. Integer scaling to one-millionth precision applies only to mean imbalance ranking; match-probability ceilings and the 55/45 check use unrounded probabilities. Previous actual partnerships remain a tie breaker when optimizing options. A time-limited missing result is reported as unfinished, never as proof of impossibility. Cancellation aborts the request; streaming disconnect detection stops the solver, with its time budget as a final bound.

`api/duel-solve.py` runs alongside Vite on Vercel, using `server/duel_service.py` and `server/duel_solver.py`. It verifies Supabase authentication and administrator access, loads authoritative roster/ratings/history, rejects generated seasons and stale snapshots, and never writes fixtures. Existing `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` also configure Python; server-only `SUPABASE_URL`/`SUPABASE_ANON_KEY` can override them. No service-role key is required. Python dependencies are pinned by `.python-version`, `pyproject.toml`, and `requirements.txt`. Real files/functions resolve before the SPA fallback; unknown API routes remain 404.

For local development, create the Python environment as described in `scripts/experiments/duel-cpsat/README.md`, set `DUEL_CPSAT_PYTHON` to its interpreter, run `npm run dev:solver`, then `npm run dev` in another terminal. Vite proxies the API to loopback port 8001. Run Python checks with `python -m unittest server.test_duel_service server.test_duel_prefilter` and `python -m unittest discover -s scripts/experiments/duel-cpsat -p test_solver.py`. The browser check below always exercises CP-SAT against a disposable database; set `DUEL_CPSAT_PYTHON` to the solver interpreter.

In **Setup → Teams & fixtures**, choose maximum total games with the same partner and maximum total games against the same individual opponent. They default to **2** and **3**, respectively. Limits count all meetings, rather than additional repeats, within this season. Each accepts an integer from one through games per player, or **No limit**. Opponent limit one is disabled because equal participation requires more encounters. Impossible combinations produce an explanation without relaxing limits.

The same four players may appear together in only one fixture per season, regardless of player order, squad side or partnership assignment. This hard rule applies in CP-SAT search, structural warm starts, client validation, plan saves and a unique database index on actual Team Duel fixtures. Individual partners or opponents may still meet up to the configured limits in different four-player groups.

New drafts have no tiers and no compulsory partner or opponent coverage. Squads of `n` give everyone `n − 1` games, with `n(n − 1)/2` fixtures total. Rounds never double-book players. Even squads have `n − 1` rounds; odd squads have `n` rounds and one bye per player.

**Search squads and schedules** checks possible squad splits in bounded CP-SAT batches. The strongest player anchors A; ratings descending, then player IDs, determine squad ranks. **Shuffle squads** searches another verified split, while **Refresh schedules** keeps the squads and seeks unseen schedules. Both preserve filters and typed names. Identical background refetches preserve previews; changed roster, ratings, history, or settings invalidate them. Cancel or leaving the page aborts unfinished work. Server unavailability gives a retryable error.

Every candidate satisfies the hard **55/45 season limit**: neither squad exceeds a 55% chance of an outright season win, conditional on an outright winner. Joint champions are excluded from this comparison and shown separately. The existing TrueSkill prediction includes rating uncertainty. Season forecasts assume independent game outcomes. **40/60 is a match-quality target**, not a hard limit; cards disclose games outside it.

For the selected squads, up to two distinct schedules appear. More variety stays within five percentage points of the Closest games result and within every hard limit:

- **Closest games** minimizes worst favorite probability, then games outside 40/60, then mean imbalance.
- **More variety** maximizes individual opponent coverage, then maximizes the fewest distinct partners any player gets, then maximizes total distinct partnerships and minimizes opponent repetitions.

Only actual matchup differences count as distinct. Fewer available options are explained. Refresh excludes previously shown schedules until its cycle is exhausted. Partnership history is a final tie breaker and counts only pairs actually used in the proposed schedule.

History covers the three immediately preceding league seasons, ordered by start date and ID; empty seasons still occupy a place. Completed round-robin and duel match snapshots identify actual partners; older round-robin matches use their two-player team. Scheduled games and forfeits are excluded. Each pair counts once per previous season.

Cards show worst and mean favorite probability, games within 40/60, opponent and partner pair coverage, the range of distinct partners per player, meeting maxima, hardest player's workload, season chances, and expected squad wins. Details show every lineup/probability, per-player games, expected wins, difficulty and distinct partners and opponents, partner/opponent count matrices, missing opponents, and rest. A separate ordering pass minimizes back-to-back appearances on one court without changing matchups.

## Saving and rollout

**Save selected squads** persists settings, squads, and the exact selected plan. Reload restores the preview when inputs match. **Generate selected matches** saves and generates that exact plan atomically; a separate save is optional. The generic generation API also reproduces saved flexible plans. Legacy exhaustive/unspecified-engine plans and experience/alternative options require a fresh CP-SAT search before saving or generating. Existing generated seasons remain readable and their results can still be corrected.

Apply all pending migrations, including `supabase/migrations/20261108173913_duel_ranking_point_limit.sql`, **before deploying the updated server and frontend**. The new migration validates ranking-point caps and requires a fresh search for fixture-free legacy-engine or removed-objective drafts. It does not rewrite saved plans or existing fixtures. Server validation independently checks roster, equal participation, rounds, caps, authoritative ratings and TrueSkill season chances, rating snapshot, and expected plan hash under existing locks. Failures roll back the transaction.

Generated seasons retain their schedule mode and frozen lineups. Legacy tier-matched and mirror schedules remain valid, including result corrections and rating replay. The former tier planner remains in compatibility paths; new editable fixture-free drafts use flexible planning. Existing fixtures are never automatically replaced and the current season is never rebuilt automatically.

Active-season administrators can rename squads without changing membership, fixtures, results, or ratings. Archived seasons remain read-only. **Clear unplayed fixtures** requires confirmation, exact reviewed fixture IDs, no recorded results or forfeits, no game on court, and no linked rating history. It atomically clears fixtures and invalidates the plan, preserving season, roster, squads, ratings, and other seasons. Search/save a fresh plan before regeneration. Advanced fixture deletion also invalidates plans through existing snapshot guards.

## Results and forecasts

Standard results require at least 11 points and a two-point margin. Forfeits award a squad point without changing ratings. All games continue after a squad clinches victory. Equal final game wins mean joint champions without a deciding game or point-differential tiebreak.

Dashboard and Matches forecast all frozen games using current ratings. Recorded wins and forfeits become fixed outcomes. Missing ratings or incomplete lineups make the forecast unavailable; games are never silently omitted. It assumes independent outcomes and does not model correlated form or partnership chemistry. After play starts, forecasts can exceed 55/45; the guardrail applies when selecting and generating drafts.
